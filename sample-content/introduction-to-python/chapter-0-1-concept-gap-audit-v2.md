# Chapter 0 and Lesson 1 concept-gap audit

Status: **Initial evidence audit of the v8 prototype**

Scope:

- canonical English Moodle content generated by `scripts/upgrade-python-sample-course-v8.php`;
- `00_start_here.ipynb` and `01_programs_values_output.ipynb`;
- the active ten-question `L1R-*` knowledge check;
- the current v8 verifier.

Ratings:

- **Present**: evidence exists and is reasonably aligned;
- **Partial**: some evidence exists, but one or more required Master columns are absent;
- **Missing**: no suitable evidence was found;
- **Not applicable yet**: intentionally belongs to a later lesson.

No live Moodle content is changed by this audit.

## Main finding

The prototype is materially better than the first version: the learner now meets programming, execution modes, values, expressions, and explicit output in a coherent order. It is not yet a finished model lesson under the stricter standard.

The largest gap is not more explanatory prose. It is the lack of a complete evidence chain:

**teach → demonstrate → practise → diagnose → test → assess → teacher support**

Chapter 0 especially relies on reading and following steps. It needs observable completion evidence and a few carefully designed contrasts. Lesson 1 has a stronger chain because its notebook and ten-question check are aligned.

## Scope correction made during the audit

`F03` originally required Boolean literals in Lesson 1. That contradicted the approved progression, which defers systematic scalar types to 1.3. The concept audit now requires numeric and string literals in 1.1; Boolean literals are mastered with `T01`. This is an example of why concept sequencing must be audited before writing more questions.

### Chapter 0 completion evidence

The Chapter 0 Notebook should become the assessment artifact. A simple completion checklist is sufficient:

1. both Code and Markdown cells exist;
2. the changed example has visible output;
3. the repaired syntax example runs;
4. the learner writes one sentence distinguishing kernel state from the saved file;
5. the file is saved, reopened, and named as instructed.

A conventional ten-question quiz is not necessary here. The operational task is better evidence.

## Lesson 1 defects and boundaries

The current knowledge check correctly focuses on the refined scope:

- instruction versus output;
- top-to-bottom execution;
- expression versus quoted text;
- basic multiplication and parentheses;
- explicit `print()`;
- a missing closing quote;
- the maintenance problem caused by repeated literals.

The active `L1R-*` check should remain. The older broad `L1-*` question definition still exists earlier in the upgrade script and is overwritten by the refined definition. It does not remain active in Moodle, but it creates a maintenance hazard: a future editor can change the wrong block. Before the prototype becomes the canonical generator, remove overwritten draft content and keep one source definition per language.

The check still needs an explicit concept-ID map. Proposed mapping:

| L1R-02 | F02 |

`V01-preview` is not an assessment of variables. The answer should only recognise why repeated literals are fragile and why the next lesson introduces names.

## Content that should be moved or removed

- Keep the course-level AI-use permission in one orientation/policy location only. Do not repeat AI-use morality checks in lesson quizzes.
- Keep the learning-centre context only when it makes a task concrete. A recurring fictional character or “next job” must not carry the explanation.
- Keep the final project connection as one precise sentence: the learner is building the ability to produce a reproducible operational report.
- Move complete type names, conversion, `/`, `//`, `%`, `**`, and floating-point behaviour to 1.3. Lesson 1 uses only the minimum arithmetic already declared by F04.
- Do not add statistics, pandas, or open-data details to these opening lessons. The course map is enough foreshadowing.

## Teacher-support gaps

Neither the Moodle page nor the Notebook is a teacher guide. Add teacher-only notes for:

- learners who type code into Markdown cells;
- learners who expect every Notebook expression to behave like script output;
- learners whose result depends on cell order;
- learners who stop after the first error;
- learners who read quoted arithmetic as calculation;
- learners who change only one copy of a repeated literal;
- prompts that lead to diagnosis without giving the final code.

Answers must remain hidden from learners until the intended release condition.

## Verifier gaps

`scripts/verify-python-course-v8-prototype.php` currently checks names, markers, quiz count, archived broad questions, and completion linkage. Extend it later to verify:

1. concept metadata or a machine-readable map exists;
2. active L1 questions map only to F01–F06 and allowed Chapter 0 concepts;
3. the two Notebook templates exist in every language adaptation;
4. notebooks contain the required evidence markers;
5. no overwritten draft content is treated as the canonical source;
6. the English and Japanese versions preserve concept IDs and assessment meaning.
