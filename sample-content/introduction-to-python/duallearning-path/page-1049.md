## Introduction

**Define the problem before changing the data**

Lesson 3.2 selected the columns and rows needed for a question. Yet correct code can still produce a false conclusion when missing values, inconsistent labels, or impossible relationships are unexplained. Data cleaning is not cosmetic editing or deleting inconvenient rows. Preserve the source, define rules first, detect violations, choose actions, and record the result.

## Learning outcomes

At the end of this lesson, you can:

- Keep source, working, and analysis-ready data separate.
- Detect conversion failures, missingness, label variation, invalid ranges, cross-field contradictions, and duplicate keys.
- Build a verification table that preserves every applicable issue reason.
- Explain the production of analysis-ready data through reconciled counts and an audit record.

## 3.3.1 Preserve the source and define quality problems

## 3.3.2 Separate source, working, and analysis-ready data

Keep `raw` as loaded. Begin processing with `clean = raw.copy()` and add flags that identify quality problems. Create `analysis` only from rows meeting the documented readiness rules. These three objects show what changed and what was not used.

```
raw = pd.read_csv(data_file)
clean = raw.copy()
print("Rows:", len(raw))
print(raw.dtypes)
print(raw.isna().sum())
```

### Inspect types, missingness, categories, and ranges first

Start with `dtypes`, `isna().sum()`, category `unique()` values, and numeric `describe()`. Those counts are the baseline. Replacing values first prevents you from distinguishing source problems from problems introduced by processing.

## 3.3.3 Handle conversion failures and missing values

`pd.to_numeric(..., errors="coerce")` converts invalid numeric text to missing. Compare the missing mask before and after conversion so an original blank and a newly failed conversion remain different issues.

```
before_missing = clean["attended"].isna()
converted = pd.to_numeric(clean["attended"], errors="coerce")
conversion_failed = converted.isna() & ~before_missing
clean["attended"] = converted
print("Source missing:", int(before_missing.sum()))
print("Conversion failures:", int(conversion_failed.sum()))
```

### Do not confuse missingness with zero

A blank attendance count means “not reported,” not necessarily “nobody attended.” Unsupported filling changes totals, averages, and rates. Flag missingness with `isna()`, then document whether the row is excluded from a calculation, quarantined for review, or corrected from an authoritative source.

**Quick check:** Before replacing a blank with zero, explain whether the two values have the same operational meaning.

## 3.3.4 Normalise labels while retaining source values

Whitespace and case differences can split one district into separate groups. Retain the source as `district_raw`, apply `str.strip()` and `str.title()` to the working value, and count affected rows. Do not merge similar-looking words without an agreed rule or mapping.

```
clean["district_raw"] = clean["district"]
clean["district"] = clean["district"].astype("string").str.strip().str.title()
changed = clean["district_raw"].astype("string") != clean["district"]
print("Changed labels:", int(changed.sum()))
```

## 3.3.5 Test ranges, cross-field constraints, and duplicates

Counts and costs have non-negative range rules. This table also defines `registered >= attended >= completed`. Give each rule a named Boolean mask and display its count. Keep missingness separate from invalidity instead of hiding all problems in one expression.

```
missing_attended = clean["attended"].isna()
completion_over_attendance = (clean["completed"].notna() & clean["attended"].notna() & (clean["completed"] > clean["attended"]))
negative_cost = clean["material_cost"].notna() & (clean["material_cost"] < 0)
print(int(missing_attended.sum()), int(completion_over_attendance.sum()), int(negative_cost.sum()))
```

### Use a business key to flag every duplicate row

If one record means one centre, month, and course, those three columns form the business key. `duplicated(subset=business_key, keep=False)` displays every row in a duplicate group. Repeated centres in different months are legitimate, so the definition must precede the test.

```
business_key = ["centre_id", "month", "course"]
duplicate_key = clean.duplicated(subset=business_key, keep=False)
print("Duplicate-key rows:", int(duplicate_key.sum()))
```

## 3.3.6 Build verification and audit evidence

Detection does not reveal the correct replacement. Correct from an authoritative source, normalise under an explicit rule, or mark a value missing or pending review when evidence is insufficient. Do not guess an impossible completion count. Retain rows and create an `analysis_ready` flag, then derive the analysis subset separately.

```
clean["analysis_ready"] = ~(missing_attended | completion_over_attendance | negative_cost | duplicate_key)
analysis = clean.loc[clean["analysis_ready"]].copy()
print("Raw:", len(raw), "ready:", len(analysis), "flagged:", int((~clean["analysis_ready"]).sum()))
```

### Preserve row-level reasons in the verification report

Rule counts do not identify the source rows a reviewer must check. Retain individual flags, append every matching reason in the published order, and select identifying columns into a verification table. Do not discard additional reasons when one row violates several rules.

```
issue_rules = [(missing_attended, 'missing attended'), (duplicate_key, 'duplicate business key')]
clean['issue'] = ''
for mask, label in issue_rules:
    clean.loc[mask, 'issue'] += label + '; '
records_to_verify = clean.loc[~clean['analysis_ready'], ['month','centre_id','course','issue']]
```

### Record the audit and validate again

Record the issue, detection rule, affected count, action, and unresolved count. A zero count documents that the check ran. Finally, assert that source rows equal analysis-ready plus flagged rows and that the analysis subset satisfies the same constraints.

```
assert len(raw) == len(clean)
assert len(clean) == int(clean["analysis_ready"].sum()) + int((~clean["analysis_ready"]).sum())
assert not (analysis["completed"] > analysis["attended"]).any()
```

## Integrated practice: a lighter rehearsal for the chapter project

**Connection to the chapter project:**

Use a tiny water-container log to rehearse explicit quality flags and an audit trail without repairing the source silently.

### What to build

Convert `litres` with `errors='coerce'`. Flag missing numbers, negative numbers, and duplicate `container_id,date` groups with `keep=False`; create separate valid and review tables.

### Completion criteria

- Preserve a deep copy of the original.

- One row may carry more than one flag.

- Every source row appears in exactly one output table.

### Step-by-step guide

1.  Use `isna()`, `< 0`, and `duplicated(..., keep=False)`.

2.  Combine flags with `|` for the review mask.

3.  Reconcile lengths after splitting.
