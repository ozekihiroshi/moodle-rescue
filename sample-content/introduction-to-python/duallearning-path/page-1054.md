## 3.4.1 Define the grain of detail and summary rows

**Quick check:** How does the meaning of one row change between the detail table and a district summary?

## 3.4.2 Group, count, and aggregate

`groupby("district")` splits matching rows, applies the same named aggregations, and combines results. Named `agg()` records output meaning; `reset_index()` restores group keys as ordinary columns.

```
district = analysis.groupby("district", dropna=False).agg(
 centre_months=("centre_id","size"), centres=("centre_id","nunique"), registered_total=("registered","sum")
).reset_index()
```

### Distinguish what size, count, and nunique count

`size` counts rows including missing values, `count` counts non-missing values in a selected column, and `nunique` counts distinct values. Centre-month records, reported attendance values, and distinct centres are different measures.

### Put a conditional count into named aggregation

Create a row-level Boolean condition, then sum True values within each group. The decision and its count remain separately inspectable.

```
operational = analysis.assign(low_completion=analysis['completion_rate'] < 75)
summary = operational.groupby('course').agg(low_records=('low_completion','sum'))
```

## 3.4.3 Calculate totals, statistics, and rates

`sum` measures volume, `mean` arithmetic centre, `median` the middle ordered value, `min` and `max` endpoints, and `std` spread around the mean. Extremes can pull the mean, so show count, median, and range. Standard deviation does not explain causes.

```
analysis.groupby("course")["registered"].agg(["size","sum","mean","median","min","max","std"])
```

### Calculate rates from compatible aggregate totals

Overall course completion is total completed divided by total registered. A simple mean of centre-month rates gives a small and a large record equal weight. It answers about a typical record, not all registered learners. State the denominator in words.

```
course = analysis.groupby("course").agg(records=("centre_id","size"),registered=("registered","sum"),completed=("completed","sum"),mean_row_rate=("completion_rate","mean"),material_cost=("material_cost","sum"))
course["overall_completion_rate"] = course["completed"] / course["registered"] * 100
course["cost_per_completion"] = course["material_cost"] / course["completed"]
```

For Python Foundations in the practice data, the simple mean row rate is about 71.9%, while 290 total completions divided by 400 total registrations is 72.5%. Similar values still have different definitions.

### Preserve comparison hierarchy with multiple keys

`groupby(["district","course"])` creates one row per pair. This differs from district-only grain. Do not add or average incompatible grains without defining their relationship.

## 3.4.4 Build indicators used for a decision

### Build a reproducible ranking from multiple conditions

Sort the primary and secondary measures descending, then a stable ID ascending. The final key resolves ties reproducibly; rank before rounding display values.

```
ranked = summary.sort_values(['average','days','id'], ascending=[False,False,True])
```

### Check the proportion denominator and 100% total

Course share within a district divides district-course registrations by that district total. The grand total answers another question. `transform("sum")` aligns denominators, and within-district shares should sum to 100%.

```
dc["district_total"] = dc.groupby("district")["registered"].transform("sum")
dc["share"] = dc["registered"] / dc["district_total"] * 100
```

**Quick check:** Why rank unrounded values and finish with a stable ID tie-break key?

## 3.4.5 Reconcile, save, and re-read the result

Grouped record, registered, completed, and material-cost totals must sum back to analysis detail. Assertions expose omitted or double-counted data. Attach counts to averages and do not interpret a small-group difference as proof of cause or superiority.

```
assert int(course["records"].sum()) == len(analysis)
assert course["registered"].sum() == analysis["registered"].sum()
assert course["completed"].sum() == analysis["completed"].sum()
```

### Save purpose-specific CSVs and validate them after re-reading

Save a verification table and a priority summary separately, then re-read and reconcile column order, row counts, and the first priority. Inspecting only the pre-save variable does not validate the submitted product.
