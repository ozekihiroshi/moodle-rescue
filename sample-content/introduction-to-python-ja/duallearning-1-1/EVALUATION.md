# Python 1.1 単元試行 — 評価とプラグインへの戻し先

2026-09-18。対象は日本語版1.1だけです。既存の第1〜6章コースは変更していません。自学自習型を選び、予習→本文・統合練習→Python Lab→復習の経路を、`format_duallearning` 0.1.0-alpha2とMarkdown原稿三つで構成しました。

## 確認できたこと

- Moodle画面で一単元と三つのLessonMark教材、Lab活動が順に見えます。見出し、表、コード、模範解答の開閉表示を確認しました。
- 学習者用概要は次の未完了教材と進捗を示します。検証用学生の初期状態は0/3で、最初に「01 始める前に」が示されました。
- 教材原稿はMarkdownファイルとMoodle内の保存内容を照合しました。ユーザー情報を除いた配布MBZでは、LTIを除外し、新規の非公開コースへ復元して三教材・順序・自学自習モードを確認しました。
- 既存Python LabへのLTI起動はローカルの構築済み試行コースで使用できます。配布MBZには含めていないため、復元先の学生アカウントでのLab起動・復帰は、各サイトのLTIを追加した後に別途確認が必要です。

## 学習者が迷いやすい点

- 「完了」は教材を読んだ印で、コードの実行成功や技能の認定ではありません。本文と復習に明記しましたが、概要だけでは区別しづらい可能性があります。
- Labを開く活動は別のサイト固有LTIです。配布版では、管理者が設定するまで経路が途切れます。公開前にLTIを配置し、学生で起動確認する手順を必須にしました。
- 課題提出がない単元でも、alpha2の概要は提出・評価欄を表示します。提出物のない単元では空欄を隠す改善候補です。

## 作成者が余分な操作をする点

- alpha2の「説明を加える」近道はMoodle標準Pageを作ります。MarkdownをLessonMarkで管理する場合は、通常の活動追加画面からLessonMarkを別途作る必要があります。単元作成画面からMarkdown教材を直接追加できる導線が次期プラグインの改善候補です。
- 活動名とMarkdown先頭のH1を両方書くと見出しが二重に見えました。原稿からH1を外して解消しました。作者向け説明で「活動名をページ見出しとして使う」と示すと重複入力を減らせます。
- Moodle標準バックアップはLTIのサイト固有設定を含み得ます。配布時は活動を除外して再設定が必要です。次期プラグインの課題というより、教材配布手順の安全性の問題です。

次の改修へ渡す優先候補は、(1) Markdown教材を単元から追加する作者導線、(2) 提出物のない単元での空欄非表示、(3) 教材完了と実行・理解の違いが分かる学習者向け文言です。これは試行観察であり、プラグインの全機能評価や第1〜6章の改訂完了を意味しません。
